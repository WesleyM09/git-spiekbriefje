# Spiekbrief Git en GitHub
## 1. Clone, commit, push en pull

Spiekbrief: Clone: Je maakt een lokale kopie van een project uit een online repository.

Spiekbrief: Commit: Je slaat je wijzigingen lokaal op met een korte beschrijving van wat je hebt aangepast.

Spiekbrief: Push: Je stuurt je lokale wijzigingen naar de online repository.

Spiekbrief: Pull: Je haalt de nieuwste wijzigingen van de online repository op naar je eigen computer.

## 2. een goed commit bericht

Spiekbrief: "Voeg puntentelling toe aan het Qwixx-spel."(1) "Code aangepast."(2):
 Het goede commitbericht beschrijft duidelijk welke aanpassing er is gebeurd. Het slechte commitbericht is te algemeen en vertelt niet wat er precies veranderd is. Daardoor is het bij het goede bericht veel gemakkelijker om later wijzigingen terug te vinden en te begrijpen.

## 3. Gitignore

Spiekbrief: Een .gitignore-bestand zorgt ervoor dat Git bepaalde bestanden en mappen niet bijhoudt in je repository.

## 4. Pull

Spiekbrief: Een pull neemt gewijzigde elementen die niet in VS Code zijn aangepast op en slaat ze op. Hierdoor kun je altijd een overzicht blijven houden hoe alles verloopt zonder een fout op te lopen.

## 5. Terugdraaien

De historiek laat je zien wat je als laatste hebt opgeslagen, dus als je elke keer iets opslaat en upload, dan kan je nog altijd terug als je iets fout of per ongeluk weg hebt gedaan.

## 6. Branches en pull requests

Een branch is een aparte versie van je repository waarin je nieuwe aanpassingen kunt maken zonder de hoofdversie te veranderen. Zo kun je veilig werken aan nieuwe functies of verbeteringen.

De branch main bevat de stabiele en werkende versie van je project. Nieuwe aanpassingen worden eerst op een aparte branch gemaakt en getest. Pas wanneer alles goed werkt, worden de wijzigingen samengevoegd met main.

Een pull request is een aanvraag om de wijzigingen van een branch samen te voegen met een andere branch, meestal main.
